## Findings

**LOW L-1 (`src/resident.ts:154,226`, `src/showhome.ts` `assertShowhomeAddressCap`).** The across-all-addresses bound no longer limits junk volume. Each unauthenticated bind or recover request from a distinct address writes one `showhome_rate` row (IPv6 rotation makes distinct addresses cheap), where before the 100/200 global cap bounded the table and the writes. This is exactly Ben's ruling (per-address stays on every attempt, global after verify) and the project already has unbounded unauthenticated per-request D1 writes elsewhere (door counters), so I do not rate it above LOW. The step-1 `DELETE ... WHERE created_at < ?` scans the table on every attempt (no index leads on `created_at`); it grows with the junk. A DEFERRED flag naming a total-rows or Cloudflare rate-limit rule as the trigger would be honest.

**LOW L-2 (`src/showhome.ts` `assertShowhomeAddressCap`, `if (!ip) return`).** A request with no `CF-Connecting-IP` reserves no slot and, until it verifies, meets no cap at all; before, it met the global cap. Cloudflare always sets the header in production, so this is a local/test-only path.

**LOW L-3 (builder's stated edge, `src/resident.ts:182,240`).** A signature-valid replay inside the 5-minute window takes a global slot, then fails at the nonce. Judged: acceptable. Bind cannot be replayed at all (the guest is already bound and is refused at `:166` before the signature step). Recover replay needs a captured valid assertion and is bounded per address by step 1. A resident holding a real key can also spend global recover slots with fresh assertions from many addresses; that is a narrower attack than the pre-change junk flood, which needed no key.

**LOW L-4 (`src/council-core.ts:187`, served on `/skill.md` and `/api/council` known_weaknesses).** "the evidence read at claim time is stored here, with a hash of each response, so the proof stays checkable" is still true of the operator's database, but after this wave the public can no longer read the stored text, so a reader can check a hash only by re-fetching the live record, which a deletion defeats (the very case the sentence addresses). Not false, now thinner. Rewording it needs a `/skill.md` version bump, so it is a follow-up, not a condition.

**LOW L-5 (cost note).** `GET /`, `GET /api/official` and `GET /api/topics` now run one more query with six `EXISTS` arms per citizen on every hit. The arms are indexed and the tables are small today; mention only because those are the three most-requested public reads on the D1 free plan.
